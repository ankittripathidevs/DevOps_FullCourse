🌸 Dockerfile for Java

# (1) Pull a base images which gives all the required tools & Libraries (stable official Java runtime base image)                            
FROM eclipse-temurin:17-jdk                                                                                                                                                          
                                                                                                                                          
# (2) Create a folder where the app code will be stored (working directory)                        
WORKDIR /app    
                                             
# (3) Copy source code from HOST machine into the container                    
COPY src/Main.java /app/Main.java   
                                                                                                                                                         
# (4) Compile the Java code                                                                        
RUN javac Main.java           
                                                                                                                                                               
# (5) Run the Java application when the container starts                                           
CMD ["java", "Main"]  


🧠 One-Line Interview Answer
--> ENTRYPOINT is used when the container should always run a specific application,
    while CMD provides a default command that users can override.


🌸 Build Images
--> docker build -t java-app .

(1) docker build:- This tells Docker to build a new image using the Dockerfile in the current folder.
(2) -t java-app:-  -t means tag
    -> java-app:- The name/tag of the image 
    -> It helps you identify the image later
    -> So this creates an image named: java-app:latest
    -> If you don’t specify the version tag, Docker automatically uses latest
(3) . The dot at the end means: Build context is the current directory

--> docker run java-app
--> docker run --name customName java-app
--> docker run -d -it --name customName java-app

docker run -d -it java-app
docker run java-app
docker run java-app bash

Under 2 scenarios:
✅ Scenario 1 → Using CMD
✅ Scenario 2 → Using ENTRYPOINT


🌸 Dockerfile (Scenario 1)
FROM eclipse-temurin:17-jdk
WORKDIR /app
COPY src/Main.java /app/Main.java
RUN javac Main.java
CMD ["java", "Main"]


Your Java program prints and exits.

🟢 SCENARIO 1 — Using CMD
--> docker run java-app

Runs default CMD: java Main
✔ Prints output
✔ Then container stops (because Java program ends)

--> docker run java-app bash

Since you're using CMD, it gets overridden.

This runs: bash
✔ Opens bash shell
✔ Java does NOT run

:- docker run -d -it java-app


Flags meaning:
-d → run in background
-i → interactive
-t → terminal

This runs: java Main

But:
✔ It prints
✔ Java exits
✔ Container stops immediately

Because your Java program is not long-running.

🟢 CMD                          Behavior               Summary
Command          	        What Runs	       Result
docker run java-app	        java Main	       Prints → exits
docker run java-app bash	bash	               Opens shell
docker run -d -it java-app	java Main 	       Background → exits

************************************************************************************************************************
🔴 SCENARIO 2 — Using ENTRYPOINT

Dockerfile
ENTRYPOINT ["java", "Main"]
--> docker run java-app

Runs: java Main
✔ Prints
✔ Exits

Same as CMD here.
:- docker run java-app bash

Because ENTRYPOINT is fixed, this becomes:

java Main bash

✔ Java still runs
✔ bash becomes argument
✔ Does NOT open shell

Very important difference.

:- docker run -d -it java-app

Runs: java Main

✔ Runs in background
✔ Still exits immediately
Because Java finishes.

🔴 ENTRYPOINT                   Behavior                    Summary
Command	                        What Runs	            Result
docker run java-app	        java Main	            Prints → exits
docker run java-app bash	java Main bash	            Java runs, not shell
docker run -d -it java-app	java Main	            Background → exits

🔥 Core Difference Between CMD and ENTRYPOINT
        Feature	                                    CMD	            ENTRYPOINT
Can override with docker run image bash?	  ✅ Yes	              ❌ No
Arguments                                         ❌ Replaced	      ✅ Appended
Flexible?	                                  Yes	             No (fixed executable)

🧠 Important Concept
Your container exits quickly because:
Container lifetime = lifetime of main process

Your Java program ends → container stops.

🎯 Interview Answer (Very Strong)

With CMD, the command can be overridden at runtime. 
With ENTRYPOINT, the command is fixed and any arguments passed are appended.
The container stops when the main process finishes.

# Base image (OS)

# Working directory
WORKDIR /app

# Copy src code to container
COPY . .

# Run the build commands

CMD ["python", "run.py"]

✅ Flask App with MySQL Docker Setup
--> A simple Flask app that interacts with a MySQL database. The app allows users to submit messages, which are then stored in the database and displayed on the frontend.

✅ Prerequisites
--> Before you begin, make sure you have the following installed:
  - Docker
  - Git (optional, for cloning the repository)

✅ Setup

(1) Clone this repository (if you haven't already)
--> git clone https://github.com/ankittripathe/two-tier-flaskapp-docker-network.git


(2) Navigate to the project directory
--> cd two-tier-flaskapp-docker-network

(3) MySQL Container Setup
--> This is used when you run the MySQL Docker container.

docker run -d \
 --name mysql-docker \ (docker customName)
-e MYSQL_ROOT_PASSWORD=root \
 -e MYSQL_DATABASE=devops \
 -p 3306:3306 \
 mysql:8

🔹 These variables are for MySQL image only.

| Variable              | Purpose                          |
| --------------------- | -------------------------------- |
| `MYSQL_ROOT_PASSWORD` | Sets root password               |
| `MYSQL_DATABASE`      | Creates database automatically   |
| `MYSQL_USER`          | (optional) create new user       |
| `MYSQL_PASSWORD`      | (optional) password for new user |

(4) MySQL configuration For Backend Container (Flask / Node / Java)

-e MYSQL_HOST=mysql-conatinerName
-e MYSQL_USER=your_username (example:- root)
-e MYSQL_PASSWORD=your_password (example:- root)
-e MYSQL_DB=your_database (example:- devops)

| Where Used           | Variables                                                               |
| -------------------- | ----------------------------------------------------------------------- |
| 🐬 MySQL Container   | `MYSQL_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` |
| 🚀 Backend Container | `MYSQL_HOST`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DB`                |


✅ To run this two-tier application using without docker-compose

(1) First create a docker image from Dockerfile
--> docker build -t flaskapp .


(2) Now, make sure that you have created a network using following command
--> docker network create custom-NetworkName

# Example
 --> docker network create two-tier

# Check network list
 --> docker network ls

# Remove network
 --> docker network rm network-Name

# Shows complete details about Docker network.
 --> docker network inspect network_name

(3) Attach both the containers in the same network, so that they can communicate with each other

(i) MySQL container

docker run -d \
    --name mysql-docker \
    --network=two-tier \
    -e MYSQL_ROOT_PASSWORD=root \
    -e MYSQL_DATABASE=devops \
    -p 3306:3306 \
    mysql:latest

(ii) flaskapp (Backend container)

docker run -d \
    --name flaskapp-docker \
    --network=two-tier \
    -e MYSQL_HOST=mysql-docker \ (This should be the container name of mysql)
    -e MYSQL_USER=root \
    -e MYSQL_PASSWORD=root \
    -e MYSQL_DB=devops \
    -p 5000:5000 \
    flaskapp:latest
