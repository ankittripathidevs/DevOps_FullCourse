--> sudo apt-get update

--> sudo systemctl start docker
--> sudo systemctl enable docker

systemctl:- A tool that controls systemd services (start, stop, restart, check status).
status:- Shows detailed information.
docker:- The service name—here it's the Docker Engine.

Step 4: Check Docker Installation
--> docker --version

🌸 Dockerfile for JAVA 

# (1) Pull a base images which gives all the required tools & Libraries (stable official Java runtime base image)                            
FROM eclipse-temurin:17-jdk                                                                                                                                                                                                                                                                
# (2) Create a folder where the app code will be stored (working directory)                        
WORKDIR /app    
                                             
# (3) Copy source code from HOST machine into the container                    
COPY src/Main.java /app/Main.java   
                                                                                                                                              
# (4) Compile the Java code                                                                        
RUN javac Main.java           
                                                                                                                                                
# (5) Run the Java application when the container starts                                           
CMD ["java", "Main"]  


🌸 Build Images
--> docker build -t java-app .

(1) docker build:- This tells Docker to build a new image using the Dockerfile in the current folder.
(2) -t java-app:-  -t means tag
    -> java-app:- The name/tag of the image 
    -> It helps you identify the image later
    -> So this creates an image named: java-app:latest
    -> If you don’t specify the version tag, Docker automatically uses latest
(3) . The dot at the end means: Build context is the current directory

--> docker run java-app
--> docker run --name custom_Name java-app
--> docker run -d -it --name custom_Name java-app

🌼 Named Volume:- Docker manages the storage location
Example:
  -v mysql-data:/var/lib/mysql

- mysql-data = Docker volume name
- /var/lib/mysql = MySQL's data directory


***************************************************************************************************
🌼 Bind Mount:- We create a folder on the host machine and use that folder for storing data

(1) Create folder
- mkdir -p /home/ubuntu/volumes/mysql

(2) Run MySQL using Bind Mount

docker run -d \
  --name mysql-container \
  -p 3306:3306 \
  --network two-tier \
  -e MYSQL_ROOT_PASSWORD=root \
  -e MYSQL_DATABASE=devops \
  -v /home/ubuntu/volumes/mysql:/var/lib/mysql \
  mysql:latest

Note:
This means: -v /home/ubuntu/volumes/mysql:/var/lib/mysql
Host folder → MySQL's data directory

/home/ubuntu/volumes/mysql = Host folder
/var/lib/mysql = MySQL container data directory

🧣 DAY-4 DOCKER COMPOSE
=================================================================================================================================================

🌸 WHAT IS DOCKER COMPOSE?
-->  Docker Compose = Manage multiple containers using one file.

# Instead of running multiple `docker run` commands, we define the configuration in one file.
-->  docker-compose.yml or
-->  docker-compose.yaml

# Then start everything with
-->  docker compose up

=====================================================================================================
🌸 BASIC DOCKER COMPOSE FILE
=====================================================================================================
# Example

   services:

      mysql:
        image: mysql:9.7

      flask-app:
        build: .

=====================================================================================================
🌸 IMPORTANT OPTIONS
=====================================================================================================
(1) services
-->  Defines the containers/services

(2) image
-->  Specifies an existing Docker image
 
     image: mysql:9.7

(3) build
-->  Builds an image using a Dockerfile

     build: .

(4) ports
-->  Maps Host Port : Container Port

     ports:
       - "5000:5000"

(5) environment
-->  Passes environment variables to the container

     environment:
       MYSQL_ROOT_PASSWORD: root

(6) depends_on
-->  Controls the startup order of services.

     depends_on:
       - mysql

(7) volumes
-->  Used to persist data, especially MySQL data.

     volumes:
       - mysql-data:/var/lib/mysql

(8) networks
-->  Connects services to a specific Docker network

     networks:
       - two-tier

(9) healthcheck
-->  Checks whether a container/service is healthy

     healthcheck:
       test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
       interval: 10s
       timeout: 5s
       retries: 5

(10) restart
-->  Defines when Docker should automatically restart a container

     restart: always

🌸 FLASK + MYSQL DOCKER COMPOSE
=====================================================================================================
docker-compose.yml

    mysql:
      image: mysql:9.7  (don't use latest for best pratice, always mention version)
      container_name: mysql-container

      ports:
        - "3606:3606"

      environment:
        MYSQL_ROOT_PASSWORD: root
        MYSQL_DATABASE: devops
        MYSQL_USER: admin
        MYSQL_PASSWORD: admin

      volumes:
        - mysql-data:/var/lib/mysql

        # Instead of keeping MySQL's data only inside the container, store it on my Ubuntu machine at 
        - /home/ubuntu/volumes/mysql:/var/lib/mysql

      networks:
        - two-tier

      restart: always

      healthcheck:
        test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-proot"]
        interval: 10s
        timeout: 5s
        retries: 5
        start_period: 60s

   flask-app:
     build:
       context: .

     container_name: flask-container

     ports:
       - "5000:5000"

     environment:
       MYSQL_HOST: mysql
       MYSQL_USER: root
       MYSQL_PASSWORD: root
       MYSQL_DB: devops

     depends_on:
        mysql:
           condition: service_healthy

     networks:
       - two-tier

     restart: always

     healthcheck:
       test: ["CMD-SHELL", "curl -f http://localhost:5000/health || exit 1"]
       interval: 10s
       timeout: 5s
       retries: 5
       start_period: 30s


networks:
  two-tier:

volumes:
  mysql-data:

-->  New Docker Hub tag: ankittripathidocker/two-tier-backend:latest

# IMPORTANT
-->  docker image tag does not create a second copy of the image's data. It creates another tag/reference pointing to the same image.

-->  docker images

-->  ankittripathidocker/two-tier-backend:latest
-->  two-tier-flask-app-flask-app:latest

-->  ankittripathidocker/two-tier-backend

# Example:
--> docker image tag two-tier-flask-app-flask-app:latest   ankittripathidocker/two-tier-backend:latest

(4) Push image
--> docker push ankittripathidocker/two-tier-backend:latest

(5) Pull image
--> docker pull ankittripathidocker/two-tier-backend:latest

(6) Run Compose using the Docker Hub Image
--> docker compose up -d


🌸  KEY CONCEPT
--> The main idea of a Docker Registry is that you don't have to build your Docker image on every machine.
--> You can:
  - Build the image once.
  - Tag it with your Docker Hub username and repository.
  - Push it to Docker Hub.
  - Pull it from any machine.
  - Use that image directly in Docker Compose.

--> This is especially useful for CI/CD and deployment because the server can pull a pre-built image rather than rebuilding the application every time.

🧣  DAY-6 Multi-Stage Docker Builds 
=================================================================================================================================================
🌸 Multi-Stage Build
--> Uses multiple FROM statements to separate build and production stages.

    Builder Stage
       ↓
    Install / Build
       ↓
    Copy required files
       ↓
    Final Stage
       ↓
    Smaller image

# Benefits:
--> Smaller image
--> Better security
--> Faster deployment
--> Useful for CI/CD


================================================================================
🌸  Single-Stage vs Multi-Stage

## Single-Stage

  FROM python:3.14
  WORKDIR /app
  COPY requirements.txt .
  RUN pip install -r requirements.txt
  COPY . .
  EXPOSE 80
  CMD ["python", "run.py"]


## Multi-Stage
  =================
  # Builder Stage
  =================
  FROM python:3.14 AS builder
  WORKDIR /app
  COPY requirements.txt .
  RUN pip install --no-cache-dir -r requirements.txt --target=/app/deps
  COPY . .


  ==================
  # Production Stage
  ==================
  FROM python:3.14-slim
  WORKDIR /app
  COPY --from=builder /app/deps /app/deps
  ENV PYTHONPATH=/app/deps
  COPY . .
  EXPOSE 80
  CMD ["python", "run.py"]

================================================================================
🌸  Important Multi-Stage Commands

 (i) FROM python:3.14 AS builder
 -->  Creates and names the builder stage.

 (ii) RUN pip install --target=/app/deps
 -->  Installs dependencies into /app/deps.

 (iii) COPY --from=builder /app/deps /app/deps
 -->  Copies dependencies from builder to final stage.
  
 (iv) ENV PYTHONPATH=/app/deps
 --> Tells Python where to find the dependencies.

==============================================================================================

🎯 (2) Attach to a Running Container
-->  docker attach containerName
-->  Connect your terminal to the container's main process


## Example
-->  docker attach flask-app

=============================================================================================

🎯 (3) Attach Using `nohup`
-->  nohup docker attach conatinerName &
-->  Run `docker attach` in the background

## Example
-->  nohup docker attach flask-app &

## Meaning
🔹 nohup -->  Keeps the command running even if the terminal closes
🔹 docker attach -->  Attaches to the container's main process
🔹 & -->  Runs the command in the background

(i) docker logs
--> View container logs

(ii) docker attach
-->  Connect to the container's main process

(iii) nohup docker attach ... &
-->  Attach in the background


(iv) For normal log monitoring, prefer
--> docker logs flask-app
